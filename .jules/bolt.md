## 2026-10-05 - Cache Static API Responses in Bulk Loops
**Learning:** When performing bulk merchandise operations, third-party API configurations (like Printify blueprint variants) remain static per item. Performing these same lookups repeatedly inside an N+1 iteration severely bottlenecks performance due to network IO latency. Using `@functools.lru_cache` perfectly eliminates this overhead. However, when caching objects that downstream logic consumes, returning mutable types (like lists) risks state contamination.
**Action:** Apply memoization caching specifically to external network-bound lookup functions (like `get_variants`) within loop-heavy code. Always force the return types to be strictly immutable (e.g., casting `list` returns to `tuple`) before returning the cached object to ensure robust thread safety and prevent regressions, and update type hints across all consuming callers.
