## 2024-07-19 - N+1 Bottleneck on Static Third-Party Metadata
**Learning:** Found an N+1 API bottleneck across multiple bulk creation scripts (`printify_manager.py`, `create_merch.py`, `merch_factory.py`). The `get_variants` function is called inside the product creation loops, repeatedly hitting the Printify variants API for the exact same blueprint and provider IDs (e.g., Gildan Tee via Monster Digital). Since blueprint variants are static metadata during a script run, making repeated network requests per product causes severe performance degradation, especially during bulk uploads of dozens of items.
**Action:** Always use `@functools.lru_cache(maxsize=None)` with immutable return types (tuples) to memoize static third-party API lookups (like print provider variants or blueprint specifications) before using them in product creation loops.
