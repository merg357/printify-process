## 2024-05-24 - N+1 Caching Bottleneck in Iterative API Workflows
**Learning:** Repetitive third-party API lookups (like querying Printify blueprint variants) within product creation loops generate significant N+1 network bottlenecks, drastically slowing down execution times when iterating over multiple products that use the same underlying blueprint data. When applying memoization (e.g. `@functools.lru_cache`) to solve this, it's critical to ensure the cached return type is immutable (like `tuple` instead of `list`) to guarantee thread safety and prevent unintended downstream state mutations from shared references across different loop iterations.
**Action:** When optimizing iterative workflows involving static or infrequently changing third-party API queries, implement `@functools.lru_cache(maxsize=None)` on the data fetching function and enforce an immutable return type (e.g. converting a parsed JSON list to a tuple). Always explicitly update typing signatures to reflect the immutable type (e.g. `-> tuple` or `-> Tuple[...]`).
